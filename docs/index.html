📞 Колл-центр MVP
Документация
Система управления сотрудниками и графиками для колл-центра технической поддержки
✓ Node.js + Express ✓ React + TypeScript ✓ PostgreSQL ✓ JWT авторизация ✓ Версия 1.2.0

📖 Введение

Система создана для централизации управления персоналом колл-центра. Заменяет разрозненные Google-таблицы и мессенджеры единой платформой.

🎯 Задача системы
Централизованное управление графиками работы, документацией и контролем присутствия сотрудников колл-центра технической поддержки.
⚡ Ключевые возможности
Создание/редактирование графиков, система заявок на изменение смен, уведомления, статистика смен, управление сотрудниками.

⚙️ Установка

ℹ️ Убедитесь, что установлены: Node.js 18+, PostgreSQL 14+, npm или yarn.

1. Распакуйте архив

unzip mvp_enhanced.zip -d call-center
cd call-center

2. Настройте базу данных PostgreSQL

# Создайте БД
psql -U postgres
CREATE DATABASE call_center_mvp;
\q

# Инициализируйте схему
psql -U postgres -d call_center_mvp -f database/init.sql

3. Настройте бэкенд

cd backend
cp .env.example .env
# Откройте .env и заполните параметры подключения к БД

npm install
npm start

4. Настройте фронтенд

cd ../frontend
cp .env.example .env
# Проверьте VITE_API_URL в .env

npm install
npm run dev
✅ Приложение доступно на http://localhost:5173
API доступен на http://localhost:3002
Документация: http://localhost:3002/docs

🔐 Руководство администратора

Управление сотрудниками

Раздел «Сотрудники» → таблица всех сотрудников. Доступные действия:

ДействиеОписание
Добавить сотрудникаКнопка в правом верхнем углу. Укажите ФИО, роль, логин, пароль.
РедактироватьИконка карандаша в строке сотрудника. Можно изменить ФИО, роль, статус.
Открыть профильКлик по строке сотрудника. В профиле доступны смены, посещения, комментарии, тесты и история.
УдалитьИконка корзины. Требует подтверждения.
Сбросить парольКнопка в форме редактирования. Пароль очищается, сотрудник регистрируется заново.
💡 Модератор тоже может открывать профили сотрудников, писать комментарии и добавлять результаты тестов, но не может менять администраторов и других модераторов или назначать эти роли.

Рассмотрение заявок

Раздел «Заявки» → список всех заявок. Фильтр по статусу: ожидающие, одобренные, отклонённые.

При одобрении заявки можно выбрать тип смены вручную. Сотрудник автоматически получает уведомление о решении.

1
Просмотр расписания
После входа открывается раздел «Мой график». Навигация по неделям кнопками «Пред.» и «След.».
2
Запрос изменения смены
Нажмите «✏️ Запросить изменение» на нужной смене или «+ Запросить смену» для новой. Для новой смены достаточно выбрать дату и тип; причина нужна при запросе редактирования. Заявка отправляется администратору и модератору.

Ожидание решения
Администратор рассмотрит заявку. Вы получите уведомление 🔔 с решением. Если отклонено — сотрудник может повторно запросить.
4
Свободное время
В разделе «Свободное время» укажите доступные часы, когда вы готовы работать вне основного расписания.

📋 Заявки на изменение смен

Сотрудник не может самостоятельно изменить смену (особенно в пределах недели). Вместо этого он создаёт заявку на изменение.

Типы заявок

ТипОписание
editИзменение существующей смены (другой тип, время)
newЗапрос новой смены на определённую дату
deleteЗапрос на удаление смены
customПроизвольный запрос с комментарием

Жизненный цикл заявки

1. Создание (pending)
Сотрудник отправляет заявку. Администратор получает уведомление. В графике ячейка помечается «!».
2. Одобрение (approved)
Администратор одобряет, при необходимости выбирает тип смены. Расписание обновляется автоматически. Сотрудник получает уведомление ✅.
2б. Отклонение (rejected)
Администратор отклоняет с комментарием. Сотрудник получает уведомление ❌ и может повторно запросить.

Система автоматически создаёт уведомления при ключевых событиях. Колокольчик в шапке показывает количество непрочитанных.

📊 Статистика

Раздел «Статистика» доступен только администратору. Показывает количество смен на каждого сотрудника за выбранный месяц.

Данные обновляются при смене месяца. Учитываются все смены со статусом, отличным от «declined».

❓ FAQ

Почему сотрудник не может изменить смену напрямую?
По бизнес-логике, только администратор вправе финально редактировать расписание. Сотрудник подаёт заявку, администратор её рассматривает. Это исключает несогласованные изменения.
Как сбросить пароль сотруднику?
Раздел «Сотрудники» → Редактировать сотрудника → кнопка «Сбросить пароль». После сброса пароль равен NULL, сотрудник должен зарегистрироваться заново через /register.
Как добавить новый тип смены?
На данный момент через SQL или API: POST /api/schedule/shift-types с телом {"name":"...", "start_time":"HH:MM", "end_time":"HH:MM", "color":"#hex"}
Не пришли уведомления — что делать?
Проверьте, что бэкенд запущен и доступен. Колокольчик использует real-time канал; если соединение временно оборвалось, интерфейс всё равно периодически обновляет данные. Убедитесь, что токен авторизации актуален (не истёк).
